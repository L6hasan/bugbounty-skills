CLASS: web cache poisoning via an UNKEYED or OVERRIDDEN request header / a cache-key differential (misconfiguration with impact) — the primitive is the header or parser differential; the oracle is a cacheable error/redirect/empty response; the escalation is stored XSS / full-site takeover.
CORE METHOD:
  1. THE GENERAL ORACLE — unkeyed-header bruteforce: the author wrote a tool that bruteforces a header list (merged with Param-Miner's) against a cacheable URL and flags a header as UNKEYED when a malformed value makes the CDN cache a response that is not normally cached. The assigned report's instance: `GET /patches/gtaiv/notes_title_update_6/GTAIVPC_TU6_Patch_Notes_FR.txt?donotpoisoneveryone=1 HTTP/1.1` + `Host: updates.rockstargames.com` + `trailer: 1` -> the cache saves a malformed `400` response, denying the content to everyone (DoS — INELIGIBLE alone per doctrine §2(d)).
  2. EXPAND THE CANDIDATE HEADER LIST FROM THE `Vary` RESPONSE HEADER: query Google BigQuery's HTTP Archive for values used in `Vary`; `Vary` names the headers a cache is SUPPOSED to key on, so any common request header absent from `Vary` on a host is a candidate. (Author's merged list: gist.github.com/iustin24/92a5ba76ee436c85716f003dda8eecc6, 2,917 lines.)
  3. NEW CACHE-KEY DIFFERENTIAL ATOMS: (a) `x-http-method-override: HEAD` — Google Cloud Buckets honour the method-override header; Fastly does not cache `405`, but `HEAD` returns a `200` with an EMPTY body that IS cached -> a poisoned empty response on a static path (GitLab assets.gitlab-static.net, $4,850; PURGE was also enabled). (b) `Fastly-host` — Fastly rejects any `Host` not on its whitelist, but a request carrying `Fastly-host: <whitelisted-host>` lets you set the `Host` header to ANY value; the author used it to inject a host header into a backend and to move a DOM-XSS page from `redacted-cdn.com` into the cache key of `assets.redacted.com` -> XSS on a different origin. (c) Apache Traffic Server (CVE-2021-27577) ignores the URL FRAGMENT when building the cache key but FORWARDS it -> `GET /<any-cache-key>#/attacker/path` (encode `#` as `%23` when the downstream proxy encodes it) caches a different path under any key; if the backend normalises `/../`, the cached body redirects users to any path -> XSS / open redirect. (d) An ILLEGAL header-name character (`\`) — Akamai does not reject it, forwards it, and caches the resulting `400` as long as `Cache-Control` is absent. (e) A CAPITALIZED `Host` — Cloudflare lowercases the host for the cache key but forwards it as sent, so any backend that behaves differently on a capitalized host is poisonable (Varnish needed a custom config; Cloudflare needed none).
  4. THE ESCALATION THE AUTHOR USED — the cache keys on a NORMALIZED form while the backend honours the RAW header: an `X-Forwarded-Host`-driven open redirect (`GET /home` + `X-Forwarded-Host: evil.com` -> `302 Location: http://evil.com/index.html`) is key-confused onto `/main.js`, so every visitor of the homepage loads attacker-controlled JavaScript -> cross-domain script execution / full site takeover; the same `X-Forwarded-Host` trust in a 301 redirect let the author redirect JS files to attacker JS on a main site + 21 subdomains (triaged Critical, max bounty).
DETECTION SIGNAL: a cacheable response (proven by `X-Cache: hit` / `Cf-Cache-Status` / timing) to a request carrying a header you control; a malformed header value that makes the CDN cache a `400`/`405`/empty `200`; a `Vary` header that omits a header the origin clearly uses; a `Fastly-host` header accepted by the edge; a URL fragment or encoded `#` that changes the served path; a static path (`/main.js`, `/assets/*`) that returns a redirect or attacker-controlled body.
