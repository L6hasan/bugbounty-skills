### [bugbountyhuntingskills.md] §17.791 — STRING-REPLACEMENT SUBSTITUTION TOKENS (`$'`, `` $` ``, `$&`, `$<n>`) ARE A NEWLINE+QUOTE SMUGGLING PRIMITIVE INTO ANY CONFIG/TEMPLATE BUILT WITH `.replace(PLACEHOLDER, userValue)`: `$'` EXPANDS TO THE TEMPLATE'S OWN TAIL, SO A 4-CHARACTER BLOCKLIST ON THE VALUE IS IRRELEVANT AND A NEW CONFIG **SECTION** (e.g. git's config-based `[hook]`) IS DECLARED — THE APP'S OWN NEXT TOOL RUN EXECUTES IT

CORE METHOD (as the report states it):

  2. Realise that `String.replace` processes `$`-patterns in the REPLACEMENT, not the template: `$'` inserts everything AFTER the match (the template's own tail — containing real quotes and newlines the blocklist never sees), `` $` `` inserts everything BEFORE it, `$&` the match itself, `$1` a capture group.
  3. Chain two of them to close the current value, emit a line break, and open a new config SECTION using bytes that came from the template, not from your input: `a@a.co$'[hook.pwn]event=pre-commit #$'command=env #` → the written `.gitconfig` parses as `[hook "pwn"] event=pre-commit, command=env` (verify with `git config --list`).
