Rule: **authorization is per-endpoint, not per-action — enumerate the parameters of a higher-privilege sibling endpoint and add them to a lower-privilege request; if the action executes, the endpoint checks the endpoint's permission and forgets the parameter's.**

ROUTE: `web_extract` on the live HackerOne report page -> HTTP 200, full body read (the `ProtectedChecklist` authorizer source, the `claimed_by_user` scope, the anonymous GraphQL query and the timeline; no fallback route needed).
STATUS: UNVERIFIED (not reproduced — no HackerOne GraphQL endpoint was called this pass; every quote below is verbatim from the report).
CLASS: broken access control / authorization bypass (CWE-863 / CWE-285) — an authorization ROLE is granted by a SCOPE query over a NULLable foreign key, and an unauthenticated (nil) requester satisfies that scope, so anonymous callers inherit a role meant for object claimants.
CORE METHOD:
  1. THE AUTHORIZER, verbatim: `class ProtectedChecklist` / `include ::ProtectedAttribute::Protector` / `model { Checklist }` / `copy_roles(ProtectedTeam) do Checklist.joins(:team) end` / `role(:CLAIMER) { |requester| claimed_by_user(requester) }` — the CLAIMER role is decided by a SCOPE, not by an explicit ownership field.
  2. THE SCOPE, verbatim: `scope :claimed_by_user, lambda { |user| where(id: ChecklistCheck.where(user_id: user).select(:checklist_id)) }` — a SUBQUERY, not an inner join.
  3. THE ROOT CAUSE, verbatim: "Instead of an inner join, a query (`ChecklistCheck.where(user_id: user).select(:checklist_id)`) is used to fetch the checklist IDs that are claimed.
