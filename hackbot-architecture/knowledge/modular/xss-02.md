  1. Applicability first, advisory's words: "a user that can create pods and persistent volumes on Windows nodes may be able to escalate to admin privileges on those nodes. CHAIN: cluster identity able to create pods + persistent volumes -> in-tree storage plugin on a WINDOWS node does not sanitize the volume's local PATH field -> kubelet writes outside the intended volume root (arbitrary path write) -> the write targets a file Windows then executes or loads -> code execution as SYSTEM on the node, i.e. "on all windows nodes on a cluster" (advisory: escalation "to admin privileges on those nodes"; High 7~8.9; CVSS 7.2 AV:N/AC:L/PR:H/UI:N/S:U/C:H/I:H/A:H; $5,000; fixed kubelet 1.28.4 / 1.27.8 / 1.26.11 / 1.25.16).

WHY IT IS A NEW GENERAL METHOD: the recorded Kubernetes entries (§13.x / #838635-family) are UNAUTHENTICATED control-plane/kubelet API exposure; this is an AUTHORIZED, low-privileged cluster identity escalating THROUGH a storage plugin's path handling on a node. ### [Bugbountyskills.md] 17.131 An INCOMPLETE DENY-LIST of framework-RESERVED routing keys is URL-authority/scheme injection: `domain` for open redirect, `script_name` to prefix a link with `javascript:` — and a widget that renders a fetched JSON `html` field as HTML turns it into a CSP-satisfying XSS (GitLab `SafeParamsHelper#safe_params`, HackerOne #946728)

CLASS/METHOD: the helper strips only `host`/`port`/`protocol` before feeding `url_for`, but Rails' `RESERVED_OPTIONS` also holds `subdomain`, `domain`, `tld_length`, `trailing_slash`, `anchor`, `params`, `only_path`, `script_name`, `original_script_name`, `relative_url_root`. Open redirect: any `ensure_canonical_path`/`build_canonical_path(routable)` route (canonical-path mismatch forced by e.g. a capital letter) + `?domain=aw.rs` → 302 to `https://aw.rs/`. Scheme injection: `script_name` is PREPENDED and can carry a scheme — `?script_name=javascript:alert(1)//` makes the page's own RSS link render `<a href="javascript:alert(1)//<user>/<proj>/-/issues.atom?feed_token=…">`. CSP RUNG: a second call site builds a widget URL from the same params (`viewer_url = url_for(safe_params.merge(viewer: viewer.type, format: :json))`), so `?script_name=/-/snippets/<id>/raw%23` (the `%23` truncates the appended suffix) NAMES a JSON endpoint whose `html` field the blob viewer inserts into the DOM: `<form>any <b>html</b> can go <button>here<a data-remote="true" data-method="get" data-type="script" href="https://gitlab.com/-/snippets/1999974/raw" …><img width="10000" height="10000"></a></button></form>`. The UJS attributes are the escape from `script-src 'self'`: they turn the whole-page anchor into a same-origin SCRIPT loader, so one click executes attacker JS in the trusted origin. The fix is to strip the FRAMEWORK's whole reserved list, not three keys.
DETECTION SIGNAL: a redirect/URL-builder echoing `?domain=`/`?subdomain=`/`?host=`/`?script_name=`/`?only_path=`/`?anchor=`; a filter that strips only host/port/protocol; a "moved to <path>" canonical redirect; generated hrefs that change when you add `script_name=`; a client widget that fetches a URL you can steer and injects a JSON field as HTML; `data-remote`/`data-type=script` links aimed at same-origin `/raw` endpoints.
CHAIN: reserved-key injection (P4-looking URL parameter) → open redirect on many routes + `javascript:` scheme inside the app's own generated links → steer the widget's fetch to attacker-authored JSON whose `html` field is rendered as HTML → an `<a data-remote data-type=script>` loader on the trusted origin → one click → the app's own UJS loads an attacker-stored same-origin `/raw` script as JavaScript → XSS with session impact despite CSP.
TRANSFERABLE TEST: append each framework-reserved key in turn (`?domain=<yours>`, `?subdomain=<yours>`, `?script_name=javascript:alert(document.domain)//`, `?only_path=false`, `?anchor=<x>`) to every redirect/link-building endpoint and diff the emitted hrefs (`grep -o 'href="[^"]*"'`); a `script_name` landing at the START of a same-origin href is a scheme-injection sink. Then find the widget that fetches a param-derived URL and inserts a JSON field as HTML — that JSON→HTML boundary plus any same-origin `/raw` route is the CSP bypass.
WHY IT IS A NEW GENERAL METHOD: the playbook's XSS material covers sinks, encodings and CSP bypasses (JSONP/`/raw`, lfs, `base-uri`), but nowhere does it treat the FRAMEWORK's reserved routing keys as the injection class: the reusable rule is that a helper's deny-list must be diffed against the framework's own reserved list, and the gap is an authority/scheme injection in every URL the app generates.
