Metadata: GitHub, "RC Between GitHub's Repo Update REST API and updateTeamsRepository GraphQL Mutation Results in Covert and Persistent Admin Access Retention", weakness Misconfiguration, severity Medium (4~6.9), CVE-2024-2440, reporter `inspector-ambitious`, submitted 2024-02-07, disclosed 2024-09-17, state Closed resolved, 50 votes, asset GitHub Enterprise Server (HARDWARE, max_severity critical).
STATUS: UNVERIFIED (not reproduced — no GHES appliance was touched this pass; every quote below is verbatim from the team summary / GitHub release notes).
CLASS: TOCTOU race / broken access control -> COVERT PERSISTENT ADMIN ACCESS RETENTION — a GraphQL permission mutation (`updateTeamsRepository`) fired while a repository is in a TRANSITIONAL state (detached, or mid-transfer) is authorized against the PRE-transition state, so an admin who should lose access retains it after the transition completes (CWE-367 / CWE-284).
CORE METHOD:
  1. THE MECHANIC, verbatim (GitHub team summary, #2357443): "A race condition in GitHub Enterprise Server allowed an existing admin to maintain permissions on a detached repository by making a GraphQL mutation to alter repository permissions while the repository is detached."
  2. THE SIBLING, verbatim (#2216036 team summary): "A race condition in GitHub Enterprise Server allowed an existing admin to maintain permissions on transferred repositories by making a GraphQL mutation to alter repository permissions during the transfer."
  3. THE VENDOR'S OWN RELEASE NOTES, verbatim (GHES 3.11.8 security fixes): "An attacker could maintain admin access to a detached repository in a race condition by making a GraphQL mutation to alter repository permissions while the repository is detached." and "An attacker could maintain admin access to a transferred repository in a race condition by making a GraphQL mutation to alter repository permissions during the transfer."
  4. THE TWO API SURFACES: the STATE CHANGE is a REST operation (repo update / repo transfer / detach); the PERMISSION MUTATION is the GraphQL `updateTeamsRepository` mutation (public schema: `UpdateTeamsRepositoryInput { repositoryId: ID!, teamIds: [ID!]!, permission: RepositoryPermission! }`). The race is BETWEEN the two surfaces.
  5. THE WINDOW: the repository is in a transitional state (detached, or mid-transfer) when the mutation is applied; the mutation's authorization is evaluated against the pre-transition state (where the actor still had the permission to grant), and the grant is not re-checked after the transition completes.
  6. THE IMPACT: the admin retains access to a repository they should have lost (covert, persistent). CWE-367 (TOCTOU); fixed in GHES 3.9.13 / 3.10.10 / 3.11.8 / 3.12.1 (CVE-2024-2440) and 3.8.12 / 3.9.7 / 3.10.4 / 3.11.1 (CVE-2023-6690).
DETECTION SIGNAL: a system with a STATE-TRANSITION operation on an object (transfer, detach, ownership change, archive, merge, rename, publish) exposed on ONE API surface (REST, SOAP, a background job) AND a separate PERMISSION-MUTATION API (GraphQL mutation, a `/permissions`/`/members`/`/share` endpoint) on ANOTHER surface; a transition that is asynchronous or multi-step (the object is in an intermediate state for a measurable window); a permission grant that is not re-validated after the transition; a repository/tenant/object the actor is being REMOVED from. TELL: the permission mutation's authorization check reads the object's state BEFORE the transition, and nothing re-checks it AFTER — so the grant survives the transition.
