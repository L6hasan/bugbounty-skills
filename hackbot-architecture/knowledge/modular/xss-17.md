STATUS: UNVERIFIED (not reproduced — no authenticator server was stood up)
CLASS: authentication / authorization bypass inside a TOKEN-VALIDATION parser — duplicate query parameters whose KEYS differ only in CASE defeat a lowercased allowlist and let the attacker CONTROL the value used for the security decision (here the K8s identity mapping = username/groups) → privilege escalation in the cluster (CWE-20 / CWE-863).
CORE METHOD (reporter's PoC + root cause):
  1. Target `POST /authenticate` of `aws-iam-authenticator` (`aws-iam-authenticator server -c config.yaml`), body `{"Spec":{"Token":"<k8s-aws-v1.…>"}}`. The token is base64url-no-padding of a presigned STS `GetCallerIdentity` URL signed with the attacker's own AWS creds; the server re-issues that STS call and maps the response ARN/AccessKeyID to a K8s identity via `mapUsers`/`mapRoles`.
