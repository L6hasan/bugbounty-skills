CLASS: broken access control / IDOR on a DELEGATED-ADMIN console API — a delegation invite scoped to "company information" still reaches a per-user folder API that accepts an ARBITRARY `userID` and returns that user's directory tree plus capability TOKENS -> cross-user folder READ, file DOWNLOAD and directory WRITE (CWE-285 / CWE-639).
CORE METHOD:
  1. THE SETUP (writeup verbatim): "Lark-suite allows highest privileged user(Primary administrator) to invite other admin's/users. The invited users are allowed to view/modify their folders in the lark app." The tester grants the invited user ONLY the company-info permission: "he was only able to access the company information but he lacked access on the files and directories of other members."
  2. THE IDOR READ (writeup verbatim: "a GET Request which takes user id in a parameter and returns the directories and tokens of that user in the response"):
     `GET /suite/admin/space_manage/user_folder?userID=6782777787976515850 HTTP/1.1` (Host: `<tenant>.larksuite.com`, `X-Csrf-Token: [Value]`, `Cookie: [Value]`) — the response lists the TARGET USER's directories and each directory's token.
  3. ENUMERATE DOWN (verbatim: "we appended another token in the parameter query and added a parentToken and we gave its value as the user's folder token we got in the response of the above request"):
     `GET /suite/admin/space_manage/user_folder?userID=[UserId]&parentToken=[PToken] HTTP/1.1` — returns "all of the files inside that parent directory as well as the unique `token` of each file inside that directory".
  4. FILE THEFT (verbatim): the per-file tokens "could be later used to download the whole file using this endpoint `https://internal-api-space.larksuite.com/space/api/box/stream/download/all/[token]/`".
  5. THE WRITE (verbatim): `POST /suite/admin/space_manage/user_folder` (same host/headers) with a leaked directory token — "the response was 200 ok and upon confirmation, we found new sub directory was created in that folder" — the delegate alters the directory STRUCTURE of users whose files they cannot legitimately access.
  6. Program summary (the impact, verbatim): "A vulnerability was found where users without Primary admin privileges were able to view/modify the directory structure of other users in their organization. This would occur after those users were invited to view/modify their folders by a Primary admin."
