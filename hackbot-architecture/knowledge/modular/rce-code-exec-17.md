Metadata: Roblox, "Reflected XSS through multiple inputs in the issue collector on Jira", weakness Cross-site Scripting (XSS) - Reflected, severity Medium (4~6.9), CVE-2018-5230, reporter `jackb898`, submitted 2018-07-11, disclosed 2020-03-24, state Closed/Resolved, asset Roblox (jira.roblox.com).
STATUS: UNVERIFIED (not reproduced — no Jira instance was touched this pass; every quote below is verbatim from the report body/comments).
CLASS: reflected XSS behind a quote-asymmetry sanitizer — the filter escapes ONE quote character but not the other, so the payload is the SAME tag with the OTHER quote character (CWE-79).
CORE METHOD:
  1. THE FINGERPRINT -> CVE STEP, verbatim: "I noticed when testing that your Jira installation at jira.roblox.com is running on version 7.6.3, which isn't the latest version. ... I found CVE-2018-5230, which isn't very helpful but it led me in the direction of the issue collector." — the CVE names the attack surface ("XSS in the issue collector") but not the inputs, so the reporter enumerated them.
  2. THE ENTRY POINT, verbatim: "1ST AREA https://jira.roblox.com/issues/?filter=-8 in the 'Updated Date' section." — the inputs are the filter form's date fields: "Put your XSS payload in 'More than [ ] minutes ago' (15 character payload limit) or in 'In range [ ] to [ ]' (No length limit, ONLY put the payload in the first box)"; then "Click Update / Payload will run." The same method works on `?filter=-7` and `?filter=-6`.
  3. THE FILTER, verbatim: "There's only one filter that I've found for these; when using certain HTML tags like "src=" and in JS alerts using alert("texthere"), it appends two backslashes, ex. if you put in this payload: `<iframe src="//google.com"></iframe>` The output in the page will be: `<iframe src=\"//google.com\"></iframe>`".
  4. THE BYPASS, verbatim: "HOWEVER I found a bypass to this filter; instead of using double quotes, simply use all single quotes in payloads. For example if you use the payload `<iframe src='//google.com'></iframe>` The output will be: `<iframe src="//google.com"></iframe>`" — the sanitizer escapes `"` (appends `\`) but leaves `'` untouched, so the attribute is emitted intact.
  5. THE IMPACT, verbatim: "the cookies from Roblox's core site are shared with this one as well ... An attacker could use carefully crafted payloads with simple social engineering to steal Roblox user's accounts." / "with XSS you can use specially designed iframes linked to your own JS content, allowing jacking of cookies and other information from the victim."
  6. THE FIX, verbatim: "Update your JIRA version to 7.6.7 or later".
DETECTION SIGNAL: a reflected input whose response shows your double-quoted attribute backslash-escaped (`src=\"//x\"`) while a single-quoted attribute is emitted verbatim; a sanitizer that appends a backslash to `"` but not to `'`; a filter form with multiple reflected fields (date ranges, "more than N minutes ago") where the payload goes in the field with NO length limit; a product whose version is behind the latest (fingerprint -> CVE -> enumerate the CVE's attack surface). TELL: the differential is visible in the RESPONSE BODY — send the same tag twice, once with `"` and once with `'`, and diff the output.
CHAIN: any visitor (primitive: a public Jira issue-collector filter page) -> send `https://jira.roblox.com/issues/?filter=-8` with the payload in the "In range [ ] to [ ]" first box (primitive: the input is reflected) -> the sanitizer escapes `"` but not `'`, so `<iframe src='//attacker/...'>` is emitted intact (escalation: the filter is defeated by a one-character change) -> the victim opens the crafted filter link and the iframe/JS runs in the `jira.roblox.com` origin (escalation: script execution) -> the core Roblox cookies are shared onto that domain, so the script reads them (impact: account takeover; the reporter's own words: "An attacker could use carefully crafted payloads with simple social engineering to steal Roblox user's accounts"). Per doctrine §8: preconditions = the victim clicks a crafted link (reflected XSS, UI:R) and the target domain shares cookies with the core site; gain = the victim's Roblox session cookie -> account takeover.
TRANSFERABLE TEST: on ANY reflected input — (1) send a benign tag with DOUBLE quotes (`<iframe src="//x"></iframe>`) and inspect the response: if the output shows `src=\"//x\"` (a backslash appended to each `"`), the sanitizer is escaping double quotes; (2) immediately resend the SAME tag with SINGLE quotes (`<iframe src='//x'></iframe>`) — if the output is unchanged, the quote-asymmetry bypass is live; (3) confirm execution with a proof-of-concept that makes an outbound request (an iframe/script to an interact-shaker URL), not just an alert; (4) where the input is a FILTER form, prefer the field with NO length limit and put the payload in the FIRST box only.
